A read-only plan marks units `old`/`live`/`new`. The agent condenses only `old` units. `--finalize` checks the edits against the plan and makes one `maint(memory): scrolls-compacted` commit. That commit writes `compacted/scrolls_compact_<yyyymmdd>_<githash>.md`, adds a `COMPACT.md` row and the `STARTER.md` entry, and tags the checkpoint. `--list`/`--show`/`--extract` read old text back. ## What just happened

1. **Designed with the user first** (`DESIGN.md`). The user settled four decisions: newer-wins base, one commit, checkpoint tag on by default, and the report named `scrolls_compact_<yyyymmdd>_<githash>.md` (date first).
2. **Built Red/Green:** `test_compact.sh` failed (17/116, only trivial negatives passing) before `compact.py` existed. The `.sh`/`.ps1` launchers are thin, as in remove/restore.
3. **Examples with real outputs:** `check_examples.py` replays every example in a demo repository with a pinned clock, so SHAs are stable, and compares outputs exactly. Writing outputs blank, watching them fail, then reading the real ones found three bugs, each fixed test-first: labels cut mid-word, "1 commits", and the plan header printed before a `--before`/`--base` error.
4. **Examples layout, at the user's request:** first two files (`EXAMPLE.md` + `EXAMPLES.md`), then merged into one `EXAMPLES.md` with Premise/Caveats on every example (reviewed on a private comparison page), then split into an index, `assets/EXAMPLES.md` (73 lines), plus `assets/examples/example_001.md`–`example_023.md`. The test fails if the index and the files drift apart.
5. **Missed on the first pass and fixed later:** the root `.claude-plugin/marketplace.json` description, the root `README.md` skills table, and the install commands in `src/scrolls/CLAUDE.md` didn't list `/scrolls-compact`. See `WISDOM.md`. The updated install commands were not re-run here: `scrolls-compact` exists only on this branch until it merges.
6. **Example viewer (Red/Green):** `assets/example-viewer.html` shows `EXAMPLES.md` and every example on one page, one tab each (Rendered/Markdown, Previous/Next, Jump to; links between the files open the matching tab), in the style of the review page's "Combined file" tab. Built by `scripts/build_example_viewer.py` (maintenance only); `tests/test_example_viewer.sh` checks it is fresh, then runs 20 browser checks online and 4 offline (plain-text fallback without `marked`). `SKILL.md` tells agents not to read the page. Each example's Premise and Caveats are in one tinted box labelled "Note" (the user chose one box and the label; two boxes with amber Caveats is a PLAN ticket to revisit). The docsite's Skills tab shows it under Explainers as "Browse the scrolls-compact examples", in an `<iframe srcdoc>`; making that work needed the viewer to stop relying on history calls (they throw there) and on bare `#tab` links (they resolve against the host page). The docsite sets `data-theme` on its embedded pages' `<html>` (in the srcdoc, and live when its theme button is used), so the viewer follows the docs' light/dark choice; the viewer's test pins that `data-theme` overrides the system mode. Its theme is Lights Out, the banner's and the docsite's, with the docsite's CSS variable names; a test compares its colors and fonts with `themes.mjs`.
7. `scrolls-compact` is linked into `.claude/skills/` and `.agents/skills/` (`make link-skills`).
