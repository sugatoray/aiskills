# GAP_CONTEXT.md — Why Each Gap Exists

The *why* behind every entry in `GAP_ANALYSIS.md`: deliberate scope cut, genuine oversight, or technical blocker. Add or remove an entry here in lockstep with `GAP_ANALYSIS.md` — one gap, one reason.

- **No independent run** — blocker, then a deliberate cut. The only agent CLI on the build machine (`claude` 2.1.197) was not logged in, so a blind run could not be made there. The user was offered a captured run to replace the hand-written sample report and answered "no need". `assets/EXAMPLE.md` and `run-code-review/meta/MAINTAINERS.md` both say the report shows the report's form, not a measured detection rate. Close this gap only with a real run; do not relabel the hand-written report.
- **Statements from documentation only** — technical blocker. Those engines and platforms were not available on the build machine. `run-code-review/meta/MAINTAINERS.md` ("Changing a checklist or pattern") lists exactly what was run and on which versions; everything else is from documentation and is recorded as such.
- **`check_formats.py` runs no external tool and reports `unchecked`** — deliberate. The skill must not install anything into the reviewed project, and the script stays standard-library only so it works wherever Python does. Running the linters is the reviewer's job, guided by each `TOOLING.md`, because which tool and which config apply is the project's choice. `unchecked` exists so a missing parser is never a silent pass. DTD entities are left unexpanded on purpose (expanding them is the attack `review_xml/SECURITY.md` describes).
- **Linux only** — technical blocker. The build machine is Linux; no Windows or macOS machine was used. Python 3.11 and 3.13 were added on 2026-11-13, when 3.13 exposed a version-specific test (`WISDOM.md`, Traps). The scripts use `pathlib`/`os.path` and `git`, with nothing known to be platform-specific, but that is untested.
- **Fourteen languages only** — deliberate scope. They are the ones the user named (seven in the first request, four more in the `--lang` list, three added with the tool-first decision). `run-code-review/meta/MAINTAINERS.md` ("Adding a language") is the procedure for the next one.
- **No workflow runs the skill's tests** — pre-existing state of the repository, not a decision made in this work. Adding CI was not asked for.
- **No subgroup `CHANGELOG.md`** — deliberate. The subgroup holds one skill, which has its own `CHANGELOG.md`; `skills/development/review/meta/MAINTAINERS.md` says not to invent shared conventions before a second skill exists. `skills/scrolls/` has a family changelog because its eight skills version in lockstep.
