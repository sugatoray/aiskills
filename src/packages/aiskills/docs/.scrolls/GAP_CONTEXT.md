# GAP_CONTEXT.md — Why Each Gap Exists

The *why* behind every entry in `GAP_ANALYSIS.md`: deliberate scope cut, genuine oversight, or technical blocker. Add or remove an entry here in lockstep with `GAP_ANALYSIS.md` — one gap, one reason.

- **`--route` not tested against live skills.sh** — blocker. The development sandbox's network policy blocks skills.sh, so lookups were tested against a local server returning the same JSON. GitHub installs (`anthropics/skills@pdf`, `@docx`) did run for real.
- **Parsing `npx skills` text output** — deliberate trade-off. `npx skills` has no machine-readable agent list or `find --json`. The agent list comes from the "Valid agents:" line printed for an invalid `--agent`, and lookups from the `owner/repo@skill` lines of `skills find`. A change to that output in a new `skills` version would break these two features (they fail loudly, not silently). `skills list --json` is structured and is used wherever possible.
- **`install -i` not tried against the real pickers** — blocker/oversight. The pickers need a person at a terminal; the tests check the exact `npx skills add` args (no `--yes`, no `--skill '*'`) under a pty. One manual `aiskills install -i` on a real machine would close it.
- **`--last-agents` reads an internal lock file** — deliberate trade-off. `npx skills` 1.7.6 has no flag for "last picked agents"; the field and path (`$XDG_STATE_HOME/skills/.skill-lock.json`, else `~/.agents/.skill-lock.json`) were read from its source. A missing or renamed field fails loudly (no agents recorded), never installs to the wrong agents. Recheck when the pinned `skills` changes.
- **`info --full` has no detected-agents list** — blocker. `npx skills` 1.7.6 detects agents internally (`detectInstalledAgents`) but prints the list nowhere a caller can read without installing; promised in the design discussion, replaced by per-agent installed counts and said so.
- **Downloads behind a proxy on older Node** — technical limit. Node's `fetch` ignores `HTTPS_PROXY` unless `NODE_USE_ENV_PROXY=1` (Node 22.21+, 24+), which `fetchJson` sets in its child process; no dependency was added for older versions. Without a proxy every supported Node works.
- **`upgrade` not run for real** — blocker. Changing the global npm install in a sandbox proves little; the flow is covered end to end with a fake npm that rewrites the package (version, added/dropped skills, EACCES). `0.9.0` and `1.0.0` are both on npm now, so the first real check is `aiskills upgrade` from 0.9.0 to 1.0.0 on a real machine (it should list `artwallbg` and `commentdrop`). Other package managers are detected by path only (pnpm `…/pnpm/global/…` with `.pnpm` store paths, `~/.bun/install/global`, `…/yarn/global`), from their documented defaults.
- **Project installs not refreshed by `upgrade`** — deliberate. aiskills keeps no record of the projects it was installed into; the summary prints `run 'aiskills install -p' in each project that uses them`.
- **No `-d/--dir`** — deliberate cut. It was offered to the user, who didn't ask for it; `cd` into the project and use `-p` instead.
- **No CI** — not requested. Publishing is a manual `npm publish` from the package folder (the `prepack` hook copies the skills in), and the tests are run by hand.
- **Windows test coverage** — deliberate cut. The stand-in `npx` used by `src/test/cli.test.mjs` is a POSIX script, and the `test:e2e` script sets `AISKILLS_E2E=1` with POSIX syntax. The package code itself handles Windows (`npx.cmd` through `cmd.exe`, the shell-character check and quoting of arguments with spaces), but those are only unit-tested (`unsafeForWindowsShell`, `quoteForCmd`), never run on a real Windows machine.
- **Hand-written skill/group lists not tested** — oversight. The generated docs, banner and doc examples are compared with the real package, but these prose tables and counts were written by hand and nothing compares them; found when they lagged one skill behind at the 0.7.0 bump (#161). A test that reads `marketplace.json` and checks each table row would close it.
- **Docs page needs network** — deliberate: it matches sugatoray/callai's page; the browser test is skipped when cdnjs is unreachable. (The site went live at https://sugatoray.github.io/aiskills/ once the user set the Pages source.)
